Setup

Around five minutes, most of it inside Google Cloud Console.

Get a Google API key

In Google Cloud Console, enable Places API (New) and create an API key. Restrict it to your domain and to that one API.

Find your Place ID

Search your business in Google's Place ID Finder and copy the ID. It starts with ChIJ.

Paste both, publish

Drop the component on a frame, paste the key and the ID into the properties panel, pick a layout. Reviews appear straight away.

Read the full setup guide for every step in detail, with the exact key restrictions to use and a fix for each error Google can return.

Worth knowing before you buy

Google returns five reviews per business. That is a hard limit of the Places API, not of this component. If a component asks you to paste your own Google API key, it reads reviews the same way and shows the same five, whichever one you buy. There is no setting, and no price, that raises it.

If you want more than five, you need a plugin, not a component. A component runs in your visitor's browser, so it only ever sees what one live request to Google returns. Passing that means syncing reviews on a server instead. Ours is Vanssay Reviews: it pulls well past five, adds Trustpilot next to Google with one combined rating, and needs no API key at all. It is a subscription rather than a one-time purchase, and the widget loads through our servers. That is the trade. If five is enough, stay here and pay once.

The API calls are billed to your Google account. Places API has a monthly free allowance that comfortably covers a typical small business site, and the built-in caching is there to keep you inside it. You control the key, so you control the spend.

Your API key is visible in the page source. That is true of every client-side integration. Restricting the key to your domain in Google Cloud Console makes it useless to anyone else, and the setup guide walks through it.
