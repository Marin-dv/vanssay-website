How to block countries on a Framer site

Framer has no built-in geoblocking. If you need to block visitors from specific countries — for licensing, legal, compliance, or spam reasons — you have three real options. Here's how each works and which one to pick.

Updated July 2026 · 5 min read

Why you can't do this in Framer itself

Framer controls design, CMS, and hosting, but it exposes no setting for visitor access by location. There is no "restrict by country" toggle anywhere in site settings, and Framer's hosting doesn't let you write server rules. So country blocking has to come from one of three layers: a plugin that checks the visitor at render time, a CDN in front of your domain, or custom code you write yourself.

Option 1: A geoblocking plugin (2 minutes, no DNS changes)

Bouncer is a Framer marketplace plugin built exactly for this. It checks each visitor's country server-side when the page loads and shows blocked visitors an access-denied screen styled to match your site, instead of a raw error page.

  1. Install Bouncer from the Framer marketplace (Insert panel → Plugins → search "block countries").
  2. Pick countries to block — or flip to allowlist mode and pick the only countries that may enter.
  3. Style the block screen: your logo, your copy, your colors. Blocked visitors see a branded page, not a 403.
  4. Publish. The rules apply on your live site immediately, and you can change them without republishing.

Because detection runs against a server API (not JavaScript guessing the locale), it can't be fooled by changing browser language, and paid plans also flag VPN and proxy traffic. If the service were ever unreachable, the site fails open — your page shows normally rather than locking everyone out.

Option 2: Cloudflare in front of your domain

If you move your domain's DNS to Cloudflare and proxy traffic through it, a free WAF custom rule can block by country before requests reach Framer. It works, but it's a heavier setup with real trade-offs on Framer specifically: you must switch nameservers, keep the proxy enabled (which Framer's own custom-domain guidance tells you to turn off to avoid SSL and redirect issues), blocked visitors get an unstyled Cloudflare error page, and rules apply to the whole domain — never a single page or section. Full comparison here: Cloudflare geoblocking on Framer: setup, limits, and an easier alternative.

Option 3: Custom code (don't)

You can paste a script into Framer's custom code that calls a geolocation API and hides the page with JavaScript. In practice this is the worst option: the content still loads (anyone can read it in DevTools or with JS disabled), free geo APIs rate-limit and leak your key, the page flashes before hiding, and you maintain it forever. Client-side hiding is cosmetic — it is not access control.

FAQ

Does Framer have built-in country blocking?

No. There is no geoblocking setting in Framer. You need a plugin, a CDN rule, or custom code — see the comparison above.

Can visitors bypass it with a VPN?

Country detection is IP-based, so a VPN can route around a plain country block. Bouncer's paid plans detect VPN, proxy, and datacenter traffic and can block it too.

Will blocking countries hurt my SEO?

Search engines crawl mostly from US IPs. As long as the US isn't blocked, your pages keep getting crawled and indexed normally. Blocking is per-visitor, not per-search-engine.

Can I block just one page instead of the whole site?

Yes — with Bouncer you choose full-page blocking or protect individual pages/sections. CDN-level blocking (Cloudflare) applies to the entire domain.
